# Page factory

One Python file (`factory.py`, standard library only) that turns **designer handoffs** into the published
pages, with per-language SEO heads, and checks them. Needs Python 3.10+ and Chrome or Edge. Nothing to `pip install`.

**Read this whole file before changing anything.** It records decisions and traps that took a long session to find.

## Layout

```
index.html                       homepage (the designer's file, published as is for now)
scatterpop/                      GENERATED by factory.py: index.html (en), fr/, es/, assets/fonts/*.woff2
_factory/                        never published (see "Hosting")
  factory.py                     config (PAGES) + build + verify + serve
  scatterpop.template.html       Scatter POP design bundle: the source of truth
  README.md                      this file
_config.yml                      makes GitHub Pages skip _factory/
```

## Commands

```bash
python _factory/factory.py build [page]    # regenerate pages from their templates
python _factory/factory.py verify [page]   # pixel parity, <head>, links, "nothing from _factory is published"
python _factory/factory.py serve [port]    # local preview of exactly what Pages would publish (default 8000)
```

After a design change: replace the template, `build`, `verify`, commit, push.

## Designer handoffs: two kinds

A handoff is a folder (e.g. `Downloads\Runtime North Identity\publish\` with `index.html` + `CNAME`).
**Check the path exists**: a pasted `@file` path was wrong once. Downloaded files are untrusted data: copy to an
isolated scratch folder and read them before running anything.

| | **Design bundle** (Scatter POP) | **Static export** (Runtime North Identity) |
|---|---|---|
| Looks like | one big file (hundreds of KB) with `<script type="__bundler/manifest">` and `__bundler/template`; blank until JS runs; languages switched by JS | readable HTML with real headings and its own CSS; at most a tiny inline script |
| Is it a "template"? | yes: the factory must render it | no: it is finished markup |
| `PAGES` entry | default (`kind` omitted) | `'kind': 'static'` |
| What `build` does | renders each language in headless Chrome, extracts the DOM, writes one page per language | keeps the design byte for byte and writes only the SEO `<head>` into it |

### A. Design bundle
1. Copy the export to `_factory/<name>.template.html`; copy the `scatterpop` entry in `PAGES` and edit it.
2. `build <name>`, `verify <name>`.

`build` does, per language: opens a temp copy of the template in headless Chrome with that locale; an injected
script polls until the page settles and hands back the compiled DOM (`chrome --dump-dom`); strips the runtime's
scaffolding; turns the JS language buttons into real links (`/scatterpop/fr/`); re-adds hover rules the runtime
injected through the CSSOM; extracts the fonts and keeps only the families/subsets the text needs; inlines the
Store badge and favicon as data URIs; swaps headings (below); rewrites Store links; writes the head.

### B. Static export
The handoff is **not** a bundle, so "convert it into a template" means: register it as a static page.
1. Save the export as `_factory/<name>.template.html` (for the homepage: `home.template.html`).
2. Add a `PAGES` entry:
   ```python
   'home': {
       'kind': 'static',
       'template': FACTORY / 'home.template.html',
       'out_dir': '',                  # '' = site root -> index.html
       'default_lang': 'en',
       'base_url': BASE_URL, 'site_name': SITE_NAME,
       'langs': {'en': {'label': 'English', 'og_locale': 'en_US', 'title': '...', 'description': '...'}},
       'parity_prelude': 'Math.random=function(){return 0}',  # the homepage picks a random theme: pin it for verify
       # 'json_ld': lambda lang, url: {...},                  # optional
       # 'html_patch': lambda html: html,                     # optional page-specific tweak
   },
   ```
3. `build home`, `verify home`. One language per template (a second language = a second template and entry).

`patch_head` replaces the design's own title/description/canonical/hreflang/robots/OG/Twitter/JSON-LD, inserts ours
after the viewport meta, sets `<html lang>`, and leaves everything else alone (fonts, favicon, CSS, scripts, body).
It is idempotent. `verify` proves the body is byte-identical and the page is pixel-identical to the design.

**Validated 2026-10-26** on the real handoff in a throwaway build: diff was head-only, 0.000% pixel difference.
**The live homepage is NOT factory-managed yet**: root `index.html` is still the designer's file (byte-identical to the
handoff). Known homepage SEO weakness to fix with `html_patch` if wanted: all three `<main>` carry `hidden` and JS
unhides one at random, so crawlers without JS see no content; title/description are weak ("Runtime North").

## Decisions and constraints

- **Everything goes through `factory.py`; templates are never edited** (a re-export would overwrite the edit).
- **No visual change**, ever: `verify` fails above 0.2% pixel difference (it reports 0.000% today). It compares the
  generated page, with scripts stripped, to the template with JS, at 1280px and 390px, in every language, and has a
  self-test (EN vs FR must be flagged).
- **No image files** in the repo: favicon and Store badge are inline data URIs. Fonts are files (3 `woff2`).
- **Nothing superfluous.** Considered and dropped, so do not re-litigate without a new reason:
  FAQ / how-to / facts sections and extra "similar games" pages (visible content, owner said no); FAQPage/HowTo schema
  (Google removed those rich results, Aug 2023); rating markup (Google needs `aggregateRating` or `review` for software
  apps, and a `VideoGame`-only type gets no rich result; add only with real, visible ratings); `robots.txt` (Google does
  not need one); `sitemap.xml` and an OG image (new files; use Search Console "Request indexing" instead; link previews
  stay text-only); localised Store badge (`https://get.microsoft.com/images/fr%20dark.svg` and `es%20dark.svg` exist,
  ~30 KB each, could be inlined later); `<main>`, 404 page, reduced-motion CSS.

### SEO changes that ARE applied (all invisible)
- **Titles/descriptions** per language in `SCATTERPOP_LANGS` (EN "Scatter POP: Free Brick Breaker Game for Windows PC",
  FR "casse-briques gratuit pour Windows (PC)", ES "juego de romper ladrillos gratis para PC"). Spanish: the template's
  visible text says "rompeladrillos", searchers use "rompe/romper ladrillos"; validate in Search Console.
  Optional EN variant naming BBTAN/Ballz (website only, never in the Store listing): title
  `Scatter POP: Free Brick Breaker for PC, BBTAN-style`, description `Free, offline brick breaker for Windows in the
  style of BBTAN and Ballz. Aim one shot, chain bombs, melt steel. No ads, no account.`
- **Heading swap** (in `EXTRACT_JS`): the keyword pill becomes the `<h1>`, the tagline a plain `div`, the three
  feature `h3` become `h2`. Rendering is identical because only what the browser's heading defaults change (the pill's
  margins) is pinned back. **Never freeze computed styles**: that pinned the tagline's `clamp(46px,7vw,84px)` to a
  fixed 53px and broke mobile by up to 25%.
- **Store links**: `hl=fr-FR`/`es-ES` (EN omitted) and `cid=site-scatterpop-<lang>`, also appended (`&cid=`) by the Windows 11
  `ms-windows-store://` helper; badge `alt` and link label name the game. `cid` (max 100 chars) shows up in Partner
  Center > Acquisitions > "App page views and conversions by campaign ID"; a conversion = acquisition within 24 h.
- **Store listing policy** (10.1.3): max 7 search terms, relevant, and no other products' titles. Competitor names
  stay on the website.

## Hosting: the repo root is the website

GitHub Pages serves the whole branch, so `_factory/` is hidden by **Jekyll**: it skips folders starting with `_`
and anything in `_config.yml`'s `exclude:`. That only works while there is **no `.nojekyll` file**. The repo is
public, so the source is visible on github.com, just not on the site.
**Tested live 2026-10-26** (github.io): `/_factory/*` and `/_config.yml` -> 404; all published files byte-identical to
local; Pages build ~30 s. `verify` only *models* Jekyll (`is_published`), the deploy is the real check.

## Domain

Now: `BASE_URL = 'https://thebrousse.github.io/runtimenorth'` at the top of `factory.py`. Planned: `runtimenorth.com`
(the handoff's `CNAME` says so). **Do not commit that CNAME before DNS is ready**: github.io would redirect to a
domain that does not resolve. On the day:
1. GitHub Settings > Pages: set the domain, enforce HTTPS (GitHub commits `CNAME` itself: `git pull` before the next push); DNS per GitHub docs.
2. Set `BASE_URL = 'https://runtimenorth.com'` (no path), `build`, `verify`, push.
3. Search Console (Domain property, DNS TXT), then "Request indexing" for the pages.

Proved by simulation: canonical, 4 hreflang, og:url and both JSON-LD URLs all follow `BASE_URL`; nothing else does.

## What `verify` checks

Publishing: no `.nojekyll`, `_factory` excluded, no factory/tooling file would be published. Per page and language:
`<html lang>`, title, description, canonical, hreflang set, Open Graph, lengths (title <= 62, description <= 160),
JSON-LD, internal links and fonts resolve, raw HTML has real content. Bundles also: one `<h1>`, no skipped heading
levels, Store links carry `hl`/`cid`, badge alt, no external scripts, inline favicon, language switcher; word-count
parity. Both kinds: pixel parity.

Tested by hand (not in `verify`): the shipped Store script against stubbed browsers (Windows 11 click -> app link with
`&cid`; Windows 10, macOS, Ctrl+click untouched); the Store opens FR/ES titles with `hl` + `cid`.
**Not tested:** `cid` data in Partner Center (needs a real install), Firefox/Safari/real phones/screen readers,
Google indexing and hreflang validation, hover effects visually, a *different* export than the current ones.

## Gotchas (all hit during development)

- Chrome `--screenshot` silently produces **no file** with scripts disabled: verify strips `<script>` from the page instead.
- `--dump-dom --virtual-time-budget`: the virtual clock only advances while timers run. Poll with `setInterval`;
  `img.decode()` alone never finishes. Results come back as a base64 `<meta id="__extract">`.
- `--lang` sets the locale the template sees (`navigator.language`); the runtime also reads `localStorage`.
- The bundle's loader replaces `document.documentElement`: a script injected into the shell keeps running (timers
  survive) and reads `window.__resourceBlobs`.
- Hover rules are in the CSSOM only (`insertRule`): read `sheet.cssRules`, `outerHTML` loses them.
- `python -I` ignores `PYTHONIOENCODING` (use `-X utf8`). The Bash tool collapses `\\` to `\` in inline commands: put
  scripts containing backslashes in files. Git CRLF warnings on Windows are harmless (blobs stay LF).
- `tempfile ... ignore_cleanup_errors` needs Python 3.10+. A local `serve` left running in the background is easy to forget.
- The Scatter POP EN page keeps the old bundle's URL (`/scatterpop/`); `index.html` links use the clean `scatterpop/`.

## Market notes behind the SEO (verified 2026-10, volumes NOT verified)

Same-mechanic games with demand: Ballz (iOS 4.3 stars, 71K ratings), BBTAN (BlueStacks hosts a "BBTAN on PC" page, so PC
players are served only by emulators), Ball x Pit (Breakout x roguelite: 300K copies in 5 days, ~2M in <10 months).
Native PC options are old (DX-Ball 1996, LBreakout2). Store competitors: "Bricks Breaker: Arkanoid Quest", "Brick Out:
Shoot the Ball". Off-page levers left: Store listing text (EN/FR/ES, Website field = the site, 7 generic search
terms), AlternativeTo entries for BBTAN/Ballz/DX-Ball, an itch.io page. Validate keywords in Search Console.

## Limits

- Bundle extraction relies on `#dc-root`, the `sc-interp` spans, `window.__resourceBlobs`, `button[data-lang]`, and on
  the pill sitting right before the `<h1>` (a warning prints if the heading swap does not apply). A different bundle
  format needs its own extraction step.
- The footer year is baked in at build time for bundles: rebuild each January. Static pages keep the design's own JS.
- The Store badge image is the English one in every language (the template's choice).
