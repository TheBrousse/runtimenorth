# Page factory

One Python file (`factory.py`, standard library only) that turns a design-tool export, which only
renders with JavaScript, into static, per-language, SEO-ready pages. Needs Python 3.10+ and Chrome
or Edge installed. Nothing to `pip install`.

```
index.html                       hand-written homepage
scatterpop/                      GENERATED by factory.py
  index.html                     English (the default language)
  fr/index.html                  French
  es/index.html                  Spanish
  assets/fonts/*.woff2           the 3 font files the pages use
_factory/                        never published (see below)
  factory.py                     config + build + verify, all in one
  scatterpop.template.html       the design export: the source of truth
_config.yml                      tells GitHub Pages not to publish _factory/
```

## Use

```bash
python _factory/factory.py build     # regenerate the pages from the template(s)
python _factory/factory.py verify    # pixel-compare, check <head> / links / what gets published
python _factory/factory.py serve     # preview at http://127.0.0.1:8000/, only what Pages would publish
```

**After a design change:** replace `_factory/scatterpop.template.html` with the new export, run
`build`, then `verify`, then commit.

**Titles, descriptions, URLs, favicon, JSON-LD:** edit the page definition at the top of `factory.py`.
(The on-page copy and its translations live in the template itself.) Moving to a custom domain is the
one-line `BASE_URL`; rebuild.

## What `build` does, per language

1. Opens a temp copy of the template in headless Chrome with that locale and has a small injected
   script hand back the compiled DOM (`chrome --dump-dom`).
2. Strips the runtime's scaffolding, turns the JS language buttons into links (`/scatterpop/fr/`...),
   and re-adds the hover rules the runtime inserted through the CSSOM (they never appear in saved HTML).
3. Extracts the fonts, keeps only the families and subsets the text needs, writes them as `woff2`.
4. Inlines the Store badge and the favicon as data URIs: **no image files** anywhere.
5. Writes `<html lang>`, title, description, canonical, hreflang (+ x-default), robots, theme-color,
   Open Graph / Twitter tags, the inline SVG favicon and JSON-LD. The only script left is the Store-link helper.

## Why `_factory/` is not on the website

The repo root is the website, so the factory hides in plain sight: GitHub Pages builds the repo with
Jekyll, and Jekyll skips folders starting with `_` and anything under `exclude:` in `_config.yml`.
That only works while there is **no `.nojekyll` file**. `verify` fails if `.nojekyll` returns, if
`_factory` leaves the exclude list, or if any factory/tooling file would be published.

The repo is public on GitHub, so the source is visible *there*, just not on the site.

**First deploy:** `verify` models Jekyll's rules but can't run Jekyll. After the first push, open
`/_factory/factory.py` and `/_config.yml` on the site: both must 404, and `/scatterpop/`,
`/scatterpop/fr/`, `/scatterpop/es/` must load. (If Pages ever fails to build, the Actions tab
shows "pages build and deployment".)

## Adding another page

Drop its design export into `_factory/`, add an entry to `PAGES` (copy the Scatter POP one), then
`python _factory/factory.py build <name>`.

## Limits to know

- The extraction targets the design tool's "dc bundle" export: it relies on `#dc-root`, the
  `sc-interp` wrapper spans, `window.__resourceBlobs` and `button[data-lang]` for the switcher. A
  different export format needs its own extraction step.
- `og:image` is off on purpose: social scrapers need a real image file, and this site keeps image
  files out of the repo. Set `og_image` in a page definition to turn it on.
- The footer year is baked in at build time; rebuild each January.
- The Store badge image is the English one in every language (the template's choice).
